# Model and Inference Query Filters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Model version metadata complete and let the Inference list query support the legacy `status=running` and `capability` filters without changing default pagination behavior.

**Architecture:** Model remains the source of truth for model capabilities. Inference takes a capability snapshot when a generation is accepted and stores it with the immutable generation spec; list filtering then happens in PostgreSQL before pagination. `status=running` is defined as desired state `running` plus runtime phase `ready`.

**Tech Stack:** Go, gRPC/protobuf generated by the repository scripts, PostgreSQL/sqlc, existing service and adapter tests.

## Global Constraints

- Do not modify Governance, KB, Console, Higress, or cluster resources in this slice.
- Preserve the existing list response pagination (`items` and `total`) when no filters are supplied.
- Preserve tenant scoping from trusted transport identity; never accept a caller-selected tenant for filtering.
- Match capabilities exactly after trimming and lower-casing; historical generations without a capability snapshot do not match a capability filter.
- `status=running` means `desired_state='running' AND runtime_phase='ready'`.
- Regenerate protobuf/sqlc output through the pinned repository workflows; do not hand-edit generated files.

# Real import end-to-end verification

日期：2026-09-15

使用本机 Docker PostgreSQL `recycling`、集群 MinIO `ani-models` 和真实
HuggingFace provider，启动临时 gRPC Model 进程并注入可信 Principal。测试流程：

1. 通过 `CreateModel` 创建外部 `model_id=tiny-gpt2`。
2. 通过 `CreateModelVersion` 创建 `main/pytorch` pending 版本（摘要留空）。
3. 通过 gRPC `ImportModel` 受理 `sshleifer/tiny-gpt2#config.json`。
4. worker due scan 领取任务，provider 元数据绑定模型/版本，下载 662 字节文件，
   流式写入 MinIO，计算并 CAS 写入 SHA256，写 artifact，置版本 ready。
5. `GetModelVersion` 返回 ready；`GetModelDownloadURL` 下载 HTTP 200，内容摘要与
   版本摘要一致。

结果：task `20b24ab2-35a0-4b45-8e1d-4933d023e7a2`、状态 `ready`、下载字节数
`662`、checksum `77a9e9830c3abeba929f5c61e0e97c398f98b4481ad75516c0be5bf038b340b0`。
随后对同一对象生成 1 秒 TTL 下载地址，等待 2 秒后请求返回 HTTP 403，过期验证通过。

## 下载过程日志

导入 worker 和执行器现在将下载生命周期写到进程标准输出，采用 JSON 结构化日志。
同一条任务会包含 `tenant_id`、`task_id`，并按以下阶段记录：

- `import task claimed`
- `import execution started`
- `provider download started`
- `provider download completed`
- `storage upload completed`
- `import version ready`
- `import task completed`

本地运行时直接查看启动命令所在终端；Kubernetes 运行时使用：

```bash
kubectl -n <model-namespace> logs deploy/<model-deployment> -f
```

日志不会输出凭据、签名下载地址或对象内容。此前临时 E2E runner 只打印最终汇总行，
没有把 logger 注入 worker，所以看不到上述阶段。补充复验（tenant
`99999999-9999-4999-8999-999999999996`，task
`685e3eea-325b-4c5c-9619-d2d93341b820`）已捕获完整 stdout；关键行如下：
